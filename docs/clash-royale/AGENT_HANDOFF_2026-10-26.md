## 2. What engine runs it, and why engine changes may be necessary

**HydrogenVM is an alpha, incomplete compatibility/emulation engine**, not a
complete old iOS installation. Treat its advertised API/CPU coverage as
capability areas, not a guarantee every app works. Missing behavior, ABI errors,
threading/lifecycle defects, graphics bugs and audio issues can require shared
engine changes. Fix those systematically and retain other apps as regressions.
Do not force every problem into a Clash binary patch.

- The archived guest is **32-bit ARMv7-A**, ARM/Thumb-2 with VFP/NEON. Its
  reported version is **2.1306.1**. It is not a modern 64-bit iPhone app.
- HydrogenVM is a **JIT-less C++ execution engine** on modern 64-bit hosts.
  It lazily decodes guest basic blocks into cached `Op` data and dispatches
  ahead-compiled C++ handlers, with block linking/fusion and execution budgets.
  It does not generate executable host machine code at runtime.
- A Mach-O loader, guest address space, guest Objective-C runtime and HLE
  implementations supply old iOS/Foundation/CoreGraphics/UIKit/etc. semantics.
  Guest 32-bit objects/pointers/structures cannot be passed directly to 64-bit
  frameworks as though their ABIs matched.
- The iPhone shell is SwiftUI plus Objective-C++ (`app/HydrogenVM/Bridge`).
  It imports IPAs, manages separate guest containers, handles touch/keyboard,
  lifecycle, live output, diagnostics and audio. The current app targets iOS 26+.
- The **current GPU path** forwards guest GLES through `HostGL`: Apple's
  `OpenGLES.framework`/EAGL on iPhone, Mesa EGL on Linux/WSL. The software
  rasterizer/shader interpreter is also present. Use `--gpu` for the functional
  WSL Clash probes. Old architecture prose claiming GLES is software-only is
  stale; inspect `src/runtime/gl/HostGL.hpp` and the actual backend.
- Audio uses shared decoder/queue/mixer code. The iPhone shell pulls the mixer
  through AVAudioEngine; the local viewer uses SDL/PulseAudio. Audio effects,
  music decode, loops, timing, transport and speaker output are separate checks.
- Local development is Windows PowerShell + Ubuntu WSL/WSLg. Linux has 4 KB
  host pages; the reported phone has 16 KB pages. A Linux pass is not a device
  ABI, native GPU, physical keyboard/audio or lifecycle qualification.

The modified Clash guest retains the original native combat/game logic and
bundled assets. It contains compiled ARMv7 local transport/save/progression
code at build time. It is still run **inside HydrogenVM**. It cannot simply be
signed as a native app for a modern 64-bit-only iPhone. A new Hydrogen IPA does
not automatically install/update the separate modified Clash guest IPA.

Important engine constraints: retain the iPhone INODE64 stat ABI (108 bytes,
64-bit inode, `st_size` at byte 60); keep synthetic Mach rights consistent; use
real glyph/layout and delegate semantics; do not hide a genuine shutdown fault
as a clean close. Shared engine fixes need fail-before/pass-after regression
evidence and the full runtime/TestLab/compatibility gates described below.

## 8. Save formats and recovery guarantees

All durable extensions share one atomic native checkpoint transaction:
write bounded temp file, flush/fsync, close, rename. No separate durable clan/
mail/request sidecars. FNV values detect accidental corruption; they are not
cryptographic authentication. Validate all extensions and native identity before
any refresh/elapsed-time snapshot can overwrite the loaded file.

| Tag | Layout / role |
| --- | --- |
| CRG1 | Four LE u32: tag `0x31475243`, native body size, avatar offset, body FNV. Body is original native home + avatar + false optional visitor flag. |
| GRT1 | Four LE u32: tag `0x31545247`, accounted Unix seconds, body FNV, header FNV over first 12 bytes. |
| GRJ1 | Five LE u32: tag `0x314a5247`, immutable reward command length, source kind, chest ID, command FNV; original 213 bytes follow. |
| GCL1 | Ten LE u32: tag, monotonic serial, operation status, original request length, immutable command length, before/after Gold, body FNV, XOR payload FNVs, header FNV over 36 bytes. |
| GCS1 | Seven LE u32: tag, payload length, count, sequence, body FNV, payload FNV, header FNV over 24 bytes; records are BE epoch/length + original chat entry. Max 64 / 32 KiB. |
| GMA1 | Eight LE u32: tag, length, count, sequence, body FNV, payload FNV, last mail-command-prefix FNV, header FNV over 28 bytes; BE epoch/length + mail entries. Max 32 / 32 KiB. |
| GCR1 | Eight LE u32: tag, entry length, sequence, epoch, body FNV, entry FNV, request-command-payload FNV, header FNV over 28 bytes; one original request entry, max 2048 bytes. |

GCL status: 0 disbanded/serial retained, 1 create pending, 2 active, 3 leave
pending, 4 settings pending. Pending operations retain pre-command state;
recovery uses original native commands and then commits completed state.
Do not combine already charged state with another replayed debit.
GMA persists after leaving clan. GCR clears entry/stamp on leave, retains
monotonic sequence. Request IDs (1,sequence) avoid chat's (0,sequence).
Reject duplicate/truncated/unknown extensions and invalid record bounds.
Do not “repair” an invalid save by silently resetting or overwriting it.
